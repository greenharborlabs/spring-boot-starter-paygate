## Decisions
- Implement a package-private JDK `HttpResponse.BodyHandler<byte[]>`/`BodySubscriber<byte[]>` boundary with a fixed 256 KiB cap, incremental byte accounting before copying, early oversized `Content-Length` rejection, subscription cancellation on overflow/deadline, and fixed body-too-large/timeout failures. Return bytes only after bounded completion; JSON parsing remains T5 work. Reject `ofString()`, post-buffer length checks, per-chunk idle timers, and caller-configurable larger limits because they permit memory or slow-drip bypasses.
- Implement deterministic JSON evidence as an atomic write from a closed field allowlist with per-field type/value validation, stable ordering, and fixed path/value-free failures. Unknown fields and arbitrary strings in constrained fields are rejected before publication rather than copied, redacted heuristically, or silently accepted; no raw-response or free-form browser-console field exists.
- Record the durable browser policy in the existing setup guide: later live browser runs may capture only allowlisted structured console codes without raw text/arguments; Playwright/browser tracing, HAR/network payload capture, video, and screenshots are disabled while real wallet/payment material is present. Any future screenshot exception requires synthetic or explicitly masked content and separate reviewed tests; T3 does not add browser tooling.
- Exercise the subscriber directly for deterministic cancellation/boundary proof and use a loopback fixture server for end-to-end exact-boundary, oversized, stalled-after-headers, and slow-drip deadline behavior. Canary tests inspect temporary artifacts, fixed exceptions/assertion diagnostics, and captured root logs without printing the canary on failure.

### Attempt 1
Reviewed revision: 17f0137348651b82864cf5cfcff70f2110184523
Verdict: rework
Findings and dispositions:
1. **P1 — Body deadline enforcement can be blocked by completion callbacks.** In `BoundedBodyHandler.java`, `failLocked` calls `body.completeExceptionally` before cancelling the subscription, on the single shared deadline executor and while holding the subscriber monitor. CompletableFuture runs non-async dependent callbacks inline. A blocking callback therefore prevents upstream cancellation and prevents all other subscribers' deadline tasks from running. `onComplete` also never checks elapsed time, so another response can then succeed after its absolute deadline. A temporary direct-subscriber probe reproduced all three effects: the first subscription remained uncancelled during its timeout callback, a second subscriber remained pending at three times its deadline, and its subsequent completion succeeded. Rework must isolate deadline enforcement from arbitrary dependent callbacks, cancel upstream before publishing failure, and prevent late successful completion when deadline execution is delayed. Add deterministic concurrent-subscriber/callback regression coverage.
2. **P2 — Null enum metadata bypasses fixed validation failures.** In `SanitizedEvidenceWriter.java`, `isValid` calls immutable `Set.of(...).contains(value)` for enum fields without rejecting null first. A normal `LinkedHashMap` with `gate = null` throws `NullPointerException` with a null message rather than the promised fixed `INVALID_EVIDENCE_MESSAGE` rejection. This violates the fixed-failure/type-validation contract for invalid metadata. Reject null consistently before enum membership checks and cover required and optional enum fields; verify no artifact is published or replaced.
